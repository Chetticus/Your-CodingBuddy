# Your job in the first two recordings

These scripts assume Vietnamese narration and a beginner learner. They are a rehearsal aid; change any sentence you would not naturally say. Keep the code, explanation and observable result aligned.

## Before pressing Record

1. Read each script aloud once. Replace stiff wording with your own phrasing; do not memorize every sentence.
2. Run the lesson's solution and rehearse the deliberate error. Know how to get back to the working version.
3. Prepare a working copy named my-work.py in the correct lesson folder. The scripts describe its initial contents. Keep the starter and solution unchanged.
4. Make the code and output readable in a small playback window. Use one editor and one run method throughout both videos.
5. Keep notes on a second screen, another device or paper. Record only the teaching window. Make a short microphone test and listen back.

## What to do on camera

Speak to one learner. A brief “Chào bạn, mình là Nam” is enough; no long biography or promotional introduction is needed. Webcam is optional. Put most screen space toward the code and terminal.

Use this rhythm: **explain the intended change → type it → ask for a prediction → pause → run → read the result together**. Do not talk over rapid typing. A few seconds of quiet gives learners time to see what changed.

Point to the exact line or value you are discussing; avoid moving the cursor constantly. Say when you switch from writing code to typing an answer in the terminal. That distinction is easy for a beginner to miss.

Introduce deliberate mistakes honestly: “Mình sẽ cố tình làm sai một chỗ.” Explain how you investigate them. Do not pretend you accidentally discovered a rehearsed bug. If a real unexpected error happens, stop and understand it before recording the explanation.

Give students time to work. At the exercise, keep the task visible and ask them to pause. Put any solution walkthrough after a clear boundary, so they can attempt it first.

## Minimum successful outcomes

| Video | Learner should be able to do | Avoid introducing yet |
|---|---|---|
| 01 | Save/run a file, change printed text, predict order, fix a missing quote with help | Variables, loops, installing packages, an entire IDE tour |
| 02 | Use two inputs, reuse their values, distinguish quoted text from names, fix a name mismatch | Numeric conversion, validation logic, files, a full account system |

## Review your take

- Listen without watching: is the goal and explanation understandable?
- Watch at a smaller size: can you read both code and output?
- Run the final working copy: does it match the recorded result?
- Keep useful reasoning; edit distracting dead time and repeated takes.
- Check that your recording includes the exercise and a clear end.
- Update the production tracker only after recording/editing actually happen.

Record video 01 first and review it before committing to the style for video 02. The actual duration matters less than whether a beginner can follow the steps and then make a small change independently.
