# CodingBuddy project context

Before frontend design or redesign work, read `design/redesign/README.md` and the documents it links.

The current user brief is for students aged 10–15, a limited curriculum, meaningful uses of coding/technology, and Vietnamese/English UI. The adult-course marketplace and E-learning brand described in older project documents are incumbent context, not the target identity.

Current phase: preparation and concept review. The user explicitly requested approval before production redesign implementation. Continue when that approval is given; do not infer it from viewing or selecting a prototype variant.

Confirmed user facts and draft recommendations are distinguished in the preparation documents. Proposed courses and unverified résumé statistics must not become public claims.

Keep existing functional and security contracts during a visual redesign unless a behavior change is explicitly scoped. After a design is approved, reconcile the canonical product/design documents rather than maintaining contradictory active rules.
